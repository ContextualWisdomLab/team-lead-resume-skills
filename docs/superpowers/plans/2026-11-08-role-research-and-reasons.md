# 직무 조사와 판단 이유 보강

## 요청과 현재 결함

사용자는 새 직무라는 이유로 미확정 처리하지 말고 그 직무를 조사하며, 글을 읽는 사람이 갖는 ‘왜?’에 답하도록 요구했다. 0.2.0은 15개 기능의 경계를 제공하지만 F08·F09 전담 공고가 없고 F13·F14·F15는 인접 공고의 일부 책임만 연결했다. 핵심 절차에는 조사보다 미확정 처리가 앞서며, 이유를 수집·보존하는 기준도 명시되지 않았다.

## 결정과 작업 순서

1. 공식 원문으로 미확보 기능의 대표 직무를 조사한다. FDE 두 고용주 사례로 새 명칭을 산출물·책임으로 해석하는 과정을 보인다. 직무·기능·사람관리 권한은 분리한다.
2. 설치된 스킬에서 먼저 수정한다. 목표 공고 우선, 근거가 부족한 새 직무는 직접 조사, 공통 책임과 회사별 차이 구별, 조사 후 남은 구체적 사실만 확인한다.
3. 문제의 중요성·선택 기준·방법의 적합성·결과의 의미를 근거 절차에 넣는다. 실제 동기·대안·인과를 발명하지 않고 짧은 글에서도 필요한 이유를 보존한다.
4. 기존 예문과 다른 Revenue Operations Lead 합성 입력을 사용한다. 기준 판본과 수정본을 각각 새 문맥에서 적용하고 외부 조사를 허용한다. 같은 기준으로 실제 출력을 대조하며 성능 향상을 가정하지 않는다.
5. 형식·참조·파일 해시와 필수 계산 테스트를 확인한다. 설치본을 개인 스킬 Git에 저장한 뒤 배포본·문서·검증 기록을 공개 저장소에 커밋한다. 원격 main·트리·공개 상태를 확인한다.
6. 기존 비공개 결정 메모에 관련 프로젝트의 적용 상태와 공개 근거 링크를 덧붙인다. 코드·스킬 본문·평가 원문은 저장소에만 둔다.

## 수용 기준과 한계

조사 누락은 실제 사례로 보완하고 근거의 범위를 정확히 적는다. 15개 기능마다 대표적인 책임의 근거를 확보하는 작업이며 모든 산업·세부 직업을 한 번에 검증하는 작업이 아니다. 새 직무를 만날 때 조사하는 절차는 계속 적용한다. 0.2.0 E16·E18의 외부 조사 금지 조건에서 나온 보류 처리는 과거 실행 기록으로 보존하며 현재 기본 동작을 뜻하지 않는다.

이번 과제는 문서형 스킬 개선이다. 계산기·서버·외부 의존성·ATS 판정 기능은 변경하지 않는다. 합성 적용 한 번의 성공을 실제 채용 성과나 일반 성능 향상으로 확대하지 않는다.
