# Team Lead Resume Skills

공개 저장소: [ContextualWisdomLab/team-lead-resume-skills](https://github.com/ContextualWisdomLab/team-lead-resume-skills)

공식 채용 공고와 실제 경력 증거를 연결해 **팀장급 이력서·경력기술서·자기소개서**를 작성하고 검토하는 Agent Skill입니다. IT·개발·AX 중심의 0.1.0에서 출발해, 0.2.0은 최종 책임 산출물을 기준으로 한 15개 기능으로 경력을 분류합니다.

스킬 이름은 **`team-lead-resume`**입니다. 사람 관리, 기술 판단, 프로젝트 실행, 사업 성과를 실제 책임에 맞춰 보여 주도록 돕습니다.

## 제공 기능

- 채용 공고의 필수·우대·업무 요구와 실제 경험을 연결하는 JD 대응표
- 공식 직책, 직속 인원, 프로젝트 인원, 채용·평가·예산 권한의 구분
- 기획·구현·검수, 개인 행동·팀 결과, 납품·현업 사용·사업 효과의 구분
- 한 책임에 한 기능을 배정하는 15개 기능 참고표와 복합 직무·직무 전환 지침
- 기능과 산업·기술·관리 범위·프로그램 속성의 구분
- 기준값·비교값·기간·분모·산식이 확인되는 성과 서술
- 수주·인식 매출·파이프라인, 예산안·승인·집행, 예상·실현 절감의 구분
- 겸직·겹친 기간을 중복 제외하는 월 단위 경력 계산기
- 지원자의 경력 흐름과 관점을 보존하는 한국어 요약·경력기술서 작성
- 회사 지정 양식·문항 순서 우선, DOCX/PDF 렌더·텍스트 추출 검증 지침
- 제출 문서와 내부 근거표·확인 질문의 분리

정기 면담의 개최만으로 코칭 내용이나 육성 효과를 만들지 않습니다. 실제 인사관리 권한과 성과가 확인되면 구체적으로 제시합니다.

## 책임 단위의 15개 기능분류

분류 단위는 직함이 아니라 **독립적으로 책임지는 최종 산출물·성과**입니다. 복합 직무는 책임을 나누고 각 책임에 기능 코드 하나만 배정합니다. 같은 성과를 여러 기능의 별도 실적으로 중복 계산하지 않습니다.

| 코드 | 기능 | 경력에서 확인하는 중심 근거 |
| --- | --- | --- |
| F01 | 전사전략·경영관리 | 기업 방향, 사업 포트폴리오, 전사 운영모델과 사업 선택 |
| F02 | 상품·서비스 기획·관리 | 고객 가치·요건·우선순위·가격·로드맵·출시/종료 결정 |
| F03 | 연구·설계·개발·창작 | 연구·모델·설계·소프트웨어·콘텐츠의 구현·검증·인도 |
| F04 | 마케팅·수요개발 | 시장 이해, 포지셔닝, 인지도·잠재고객·유입·수요 |
| F05 | 영업·거래개발 | 수주·판매·계약·거래조건·갱신·확장 매출 |
| F06 | 조달·공급자관리 | 공급자 선정·구매조건·조달계약·공급자 성과 |
| F07 | 수급·재고·물류관리 | 수급계획·재고·보관·운송·배송·물자 가용성 |
| F08 | 생산·현장·전문서비스 제공 | 생산·시공·현장 실행, 진료·돌봄·수업 등 본원 서비스 제공 |
| F09 | 고객지원·이용성과관리 | 문의·불편 해결, 도입·활용 정착과 고객의 사용 성과 |
| F10 | 재무·회계·자금관리 | 예산·예측·결산·세무·자금·재무 공시·투자평가 |
| F11 | 인사·조직·노무관리 | 인력·역량 확보, 배치·평가·보상·육성·고용관계 |
| F12 | 운영기반·자산관리 | 정보서비스·데이터 플랫폼·시설·설비·행정 기반의 가용성·유지 |
| F13 | 품질·안전·환경관리 | 별도 품질 승인·검증, 물리적 안전·보건·환경 관리 |
| F14 | 법무·준법·내부통제 | 법적 권리·의무·규제 해석, 준법·위험 통제·감사·보증 |
| F15 | 대외관계·기업소통 | 비거래 이해관계자·정책·평판·투자자·언론 관계와 기업정보 전달 |

이는 경력 근거를 찾기 위한 사용자 정의 기능분류이며, 공식 직업 코드나 모든 회사의 필수 요건이 아닙니다. 공고의 독립 책임을 대조해 미배정·다중배정·성과 중복을 점검하는 방식으로 MECE를 확인합니다. 모든 산업의 직무를 보편적으로 포괄한다고 주장하지 않습니다. 포함·제외 경계와 미확정 처리 기준은 [직무별 참고표](skills/team-lead-resume/references/role-families.md)에 있습니다.

| 기능과 별도로 기록하는 속성 | 예시 |
| --- | --- |
| 산업·서비스 분야 | 제조, 금융, 의료, 교육, 유통, 공공 |
| 기술·전문 수단 | AI, 데이터, 클라우드, ERP, 공법·장비 |
| 역할·관리 범위 | 실무·전문 리드·프로젝트 리드·사람 관리자, 실제 인사·예산 권한 |
| 운영 대상 | 내부 조직·외부 고객, 지역·고객군·제품·시설·법인 범위 |
| 프로그램·업무 방식 | AX·DX, SCM, ESG, PMO, 프로젝트·상시 운영 |

예를 들어 경영지원 팀장의 예산 산출은 F10, 채용제도 운영은 F11로 각각 분류합니다. 다른 기능 팀장의 일상 코칭은 관리 범위로 기록하며 별도 HR 직무로 세지 않습니다. 기술이나 프로그램 명칭만으로 기능을 정하거나 프로젝트 조율을 구현·승인 권한으로 확대하지 않습니다.

## 사용 예

```text
$team-lead-resume
첨부한 채용 공고와 경력 자료를 대조해 팀장급 이력서와 경력기술서를 작성해 주세요.
회사의 지정 양식과 문항 순서를 유지하고, 개인 역할과 팀 결과를 구분하세요.
미확인 수치·직함·인원·경력 인정 여부는 추정하지 말고 별도 확인 사항으로 알려 주세요.
```

입력으로 공고 원문/URL, 경력 자료, 제출 양식, 원하는 문서 종류와 형식을 제공합니다. 자료가 부족한 항목은 확인하고 나머지 작성을 진행합니다. 실제 지원서 제출과 채용담당자 전송은 별도의 사용자 요청이 필요합니다.

복합 직무에서는 다음처럼 범위를 지정할 수 있습니다.

```text
$team-lead-resume
경영지원 팀장 공고와 제 경력을 대조해 주세요.
사업계획·예산·채용 운영 경험을 함께 보되, 제가 제안·운영한 일과 대표가 최종 승인한 일을 구분하세요.
```

## 계산과 검증

Python 3.10 이상, 외부 Python 패키지 없이 실행합니다.

```bash
python3 skills/team-lead-resume/scripts/career_months.py periods.json --as-of 2026-10
python3 -m unittest discover -s tests -v
```

입력 스키마와 계산 예시는 [경력 연수 절차](skills/team-lead-resume/references/evidence-workflow.md#3-경력-연수)에 있습니다. 현재 재직은 `end: null`, 포함 여부는 명시적 boolean이며 제외 기록에는 이유가 필요합니다.

계산기는 시작·종료 월을 포함한 월 합집합만 계산합니다. 유관 경력 여부, 시간제 경력의 환산, 정확한 재직 일수, 채용사의 필수 연수 충족을 결정하지 않습니다.

## 근거와 한계

현재 출처 장부에는 공식 채용 공고 12건(H1–H12)과 공식 지침 5건(G1–G5)이 있습니다. 지침은 역할·문서 관련 3건과 직무분류 관련 2건(G4 ILO·ISCO, G5 NCS)입니다. 공고에는 팀장·인사관리, 기술·제품·프로젝트 리드, 관련 시니어 역할을 포함하며 각 사례의 책임과 권한 범위를 따로 기록합니다.

**기능분류의 범위와 확보한 공고의 범위는 다릅니다.** F08의 생산·시공·의료·교육 등 본원 서비스와 F09의 고객지원·활용 정착 전담 공고는 아직 확보하지 않았습니다. F13·F14·F15는 다른 공고에 포함된 일부 책임만 확인했으며, 비IT 연구·창작과 시설·설비·행정 등도 추가 조사가 필요합니다. 미확보 영역은 사용자가 제공한 실제 공고와 경력으로 작성할 수 있으나, 조사하지 않은 채용 요건을 보태지 않습니다.

공고 사례는 고용주가 공개한 요구사항입니다. 합격자 원문·입사 결과를 확인한 사례나 시장 전체의 대표 표본이 아닙니다. 대학 지침은 교육 권고, ATS 문서는 해당 제품의 동작 설명이며 서로 같은 근거로 취급하지 않습니다. ILO·NCS 자료는 분류 설계의 참고 근거이며 F01–F15와 공식적으로 대응하거나 이 분류의 MECE를 인증하지 않습니다.

기존 실행 기록은 계산 테스트와 소수 합성 과제에 한정합니다. C(영업·구매)·D(경영지원)는 MECE 이전 후보의 관찰 기록이며 현재 15기능 분류의 검증 결과가 아닙니다. E의 25개 합성 사례는 한 번의 적용에서 수용 기준을 모두 충족했습니다. [MECE 검증 기록](evaluations/role-expansion/review-mece.md)에 실제 출력·판본·한계를 기록했습니다. 기존 기준 응답도 핵심 사실을 이미 보존했으므로 일반적인 성능 향상, ATS 점수, 서류 통과율, 채용 성공을 주장하지 않습니다. 실제 지원자의 자료와 기업 시스템에서의 검증은 별도 과제입니다.

개인 이력서·연락처·보상정보·사내 원문을 저장소에 넣지 않습니다. 추가 개발 범위와 미완료 항목은 [제품·기술 Gap 기준선](docs/product-technical-gap-baseline.md)을 참조하세요.
