# Team Lead Resume Skills

공개 저장소: [ContextualWisdomLab/team-lead-resume-skills](https://github.com/ContextualWisdomLab/team-lead-resume-skills)

공식 채용 공고의 요구와 지원자의 실제 경력 근거를 연결해 **팀장급 이력서·경력기술서·자기소개서**를 작성하고 검토하는 Agent Skill입니다. 현재 버전은 0.3.4입니다. 최종적으로 책임지는 산출물에 따라 직무를 15개 기능으로 분류하고, 새로 다루는 직무를 직접 조사합니다. 경력을 서술할 때는 판단의 이유와 결과의 의미를 설명합니다. 한국 테크 기업의 채용 공고와 리더 역할 인터뷰도 비교 자료로 제공합니다.

스킬 이름은 **`team-lead-resume`**입니다. 사람 관리, 기술 판단, 프로젝트 실행, 사업 성과를 실제 책임에 맞춰 보여 주도록 돕습니다.

## 제공 기능

- 공고의 직무 설명(JD)에 적힌 필수 요건·우대 사항·담당 업무와 실제 경험을 연결하는 대응표
- 공식 직책, 직속 인원, 프로젝트 인원, 채용·평가·예산 권한의 구분
- 기획·구현·검수, 개인 행동·팀 결과, 납품·현업 사용·사업 효과의 구분
- 책임마다 기능 하나를 배정하는 15개 기능 참고표와 복합 직무·직무 전환 지침
- 기능과 산업·기술·관리 범위·프로그램 속성의 구분
- 새로 다루는 직무의 공식 공고·역할 자료 조사, 공통 책임과 회사별 차이 비교
- 문제의 중요성, 방법·우선순위의 선택 근거, 확인된 결과의 의미를 연결하는 서술
- 기준값·비교값·기간·분모·산식을 확인하는 성과 서술 절차
- 수주·인식 매출·파이프라인, 예산안·승인·집행, 예상·실현 절감의 구분
- 겸직 등으로 겹친 재직 기간을 한 번만 계산하는 월 단위 경력 계산기
- 지원자의 경력 흐름과 관점을 보존하는 한국어 요약·경력기술서 작성
- 회사 지정 양식·문항 순서를 지키고 DOCX/PDF 렌더링·텍스트 추출 결과를 확인하는 지침
- 제출 문서와 내부 근거표·확인 질문의 분리

정기 면담을 했다는 사실만으로 코칭 내용이나 육성 효과를 추정하지 않습니다. 실제 인사관리 권한과 성과가 확인되면 구체적으로 제시합니다.

## 책임 단위의 15개 기능분류

**독립적으로 책임지는 최종 산출물·성과**를 기준으로 분류합니다. 여러 기능을 맡는 복합 직무는 책임을 나누고 각 책임에 기능 코드 하나만 배정합니다. 직함만으로 기능을 정하거나 같은 성과를 여러 기능의 별도 실적으로 중복 계산하지 않습니다.

| 코드 | 기능 | 경력에서 확인하는 중심 근거 |
| --- | --- | --- |
| F01 | 전사전략·경영관리 | 기업 방향, 사업 포트폴리오, 전사 운영모델과 사업 선택 |
| F02 | 상품·서비스 기획·관리 | 고객 가치·요건·우선순위·가격·로드맵·출시/종료 결정 |
| F03 | 연구·설계·개발·창작 | 연구·모델·설계·소프트웨어·콘텐츠의 구현·검증·인도 |
| F04 | 마케팅·수요개발 | 시장 이해, 포지셔닝, 인지도·잠재고객·유입·수요 |
| F05 | 영업·거래개발 | 수주·판매·계약·거래조건·갱신·확장 매출 |
| F06 | 조달·공급자관리 | 공급자 선정·구매조건·조달계약·공급자 성과 |
| F07 | 수급·재고·물류관리 | 수급계획·재고·보관·운송·배송·물자 가용성 |
| F08 | 생산·현장·전문서비스 제공 | 생산·시공·현장 실행, 진료·돌봄·수업 등 본원 서비스 제공 |
| F09 | 고객지원·이용성과관리 | 문의·불편 해결, 도입·활용 정착과 고객의 사용 성과 |
| F10 | 재무·회계·자금관리 | 예산·예측·결산·세무·자금·재무 공시·투자평가 |
| F11 | 인사·조직·노무관리 | 인력·역량 확보, 배치·평가·보상·육성·고용관계 |
| F12 | 운영기반·자산관리 | 정보서비스·데이터 플랫폼·시설·설비·행정 기반의 가용성·유지 |
| F13 | 품질·안전·환경관리 | 별도 품질 승인·검증, 물리적 안전·보건·환경 관리 |
| F14 | 법무·준법·내부통제 | 법적 권리·의무·규제 해석, 준법·위험 통제·감사·보증 |
| F15 | 대외관계·기업소통 | 비거래 이해관계자·정책·평판·투자자·언론 관계와 기업정보 전달 |

이 표는 경력 근거를 찾기 위한 사용자 정의 기능분류입니다. 공식 직업 코드나 모든 회사의 필수 요건을 제시하는 표는 아닙니다. 공고의 독립 책임을 대조하면서 배정되지 않은 책임, 여러 기능에 겹쳐 배정된 책임, 중복 계산된 성과를 점검합니다. 이런 방식으로 해당 책임 목록의 누락과 중복을 확인하며, 모든 산업의 직무를 포괄한다고 주장하지 않습니다. 포함·제외 경계와 새 직무 조사 절차, 조사 후에도 남는 확인 사항의 처리 기준은 [직무별 참고표](skills/team-lead-resume/references/role-families.md)에 있습니다.

| 기능과 별도로 기록하는 속성 | 예시 |
| --- | --- |
| 산업·서비스 분야 | 제조, 금융, 의료, 교육, 유통, 공공 |
| 기술·전문 수단 | AI, 데이터, 클라우드, ERP, 공법·장비 |
| 역할·관리 범위 | 실무·전문 리드·프로젝트 리드·사람 관리자, 실제 인사·예산 권한 |
| 운영 대상 | 내부 조직·외부 고객, 지역·고객군·제품·시설·법인 범위 |
| 프로그램·업무 방식 | AX·DX, SCM, ESG, PMO, 프로젝트·상시 운영 |

예를 들어 경영지원 팀장의 예산 산출은 F10, 채용제도 운영은 F11로 각각 분류합니다. 다른 기능을 맡는 팀장의 일상적인 코칭은 그 기능의 관리 범위로 기록하며 별도 HR 직무로 세지 않습니다. 기술·프로그램의 명칭만으로 기능을 정하거나, 프로젝트를 조율했다는 사실만으로 구현·승인 권한이 있었다고 쓰지 않습니다.

## 새 직무와 ‘왜?’를 다루는 방법

직무명이 낯설거나 출처 장부에 해당 자료가 없으면 그 직무를 조사합니다. 목표 공고를 먼저 읽고, 책임이 불명확하거나 목표 공고가 없으면 서로 다른 고용주의 공식 자료를 비교합니다. 여기서 목적·산출물·결정권·성과 기준을 확인하고 책임을 분류합니다. 회사별 권한이나 대표 책임의 우선순위처럼 조사 후에도 확인하지 못한 구체적인 사실만 추가 질문으로 남깁니다.

경력 자료에서는 왜 중요한 문제였는지, 왜 그 방법·범위·순서를 택했는지, 결과가 어떤 기준에서 의미 있는지 찾습니다. 실제로 검토한 대안과 당시 판단 기록을 보존하고, 공고에 적힌 일반적인 직무 목적을 지원자 개인의 동기로 바꾸지 않습니다. 글을 줄일 때도 핵심 판단을 이해하는 데 필요한 이유는 남깁니다. 모든 항목을 같은 순서의 긴 문장으로 늘리지는 않습니다. 수정 전후의 합성 예문과 이유가 부족할 때의 질문은 [경력 증거 절차](skills/team-lead-resume/references/evidence-workflow.md)에 있습니다.

## 한국 테크 기업 사례

한국 테크 기업 사례는 [국내 기업 비교표](skills/team-lead-resume/references/hiring-cases.md#한국-테크-기업-사례-비교)에서 확인할 수 있습니다. 기존 INTERX·토스증권·토스뱅크·채널코퍼레이션 사례에 다음 자료를 추가했습니다.

| 추가 자료 | 종류 | 사례 번호 |
| --- | --- | --- |
| 당근 Product Manager - 광고 (광고 상품) | 공식 채용 공고 | H21 |
| 오늘의집 Product Owner Lead (Commerce Platform) | 공식 채용 공고 | H22 |
| 뱅크샐러드 Platform Product Lead | 공식 채용 공고 | H23 |
| 우아한형제들 기술이사 소개 | 공식 역할 인터뷰, 2020-08-12 | G6 |
| 네이버웹툰 5주년 구성원·Lead 인터뷰 | 공식 역할 인터뷰, 2022-05-26 | G7 |

각 사례에는 확인한 책임과 권한의 범위, 기능분류의 근거, 경력에서 답할 ‘왜?’ 질문을 연결했습니다. 한국 테크 기업이라는 회사·시장 맥락은 기능과 별도로 기록합니다. 과거 인터뷰의 설명은 현재 채용 요건으로 사용하지 않습니다.

## 사용 예

```text
$team-lead-resume
첨부한 채용 공고와 경력 자료를 대조해 팀장급 이력서와 경력기술서를 작성해 주세요.
회사의 지정 양식과 문항 순서를 유지하고, 개인 역할과 팀 결과를 구분하세요.
미확인 수치·직함·인원·경력 인정 여부는 추정하지 말고 별도 확인 사항으로 알려 주세요.
```

공고 원문이나 URL, 경력 자료, 제출 양식, 원하는 문서 종류와 형식을 입력으로 제공합니다. 자료가 부족한 항목은 별도로 확인하면서 나머지 작성을 진행합니다. 실제로 지원서를 제출하거나 채용담당자에게 전송하려면 별도의 사용자 요청이 필요합니다.

복합 직무에서는 다음처럼 범위를 지정할 수 있습니다.

```text
$team-lead-resume
경영지원 팀장 공고와 제 경력을 대조해 주세요.
사업계획·예산·채용 운영 경험을 함께 보되, 제가 제안·운영한 일과 대표가 최종 승인한 일을 구분하세요.
```

## 계산과 검증

Python 3.10 이상에서 외부 Python 패키지 없이 실행합니다.

```bash
python3 skills/team-lead-resume/scripts/career_months.py periods.json --as-of 2026-10
python3 -m unittest discover -s tests -v
```

입력 스키마와 계산 예시는 [경력 연수 절차](skills/team-lead-resume/references/evidence-workflow.md#3-경력-연수)에 있습니다. 현재 재직 중이면 `end: null`로 표시합니다. 기간의 포함 여부는 boolean 값으로 명시하고, 제외하는 기록에는 이유를 적어야 합니다.

계산기는 시작·종료 월을 포함한 기간의 월 단위 합집합을 계산합니다. 유관 경력 여부, 시간제 경력의 환산, 정확한 재직 일수, 채용사의 필수 경력 연수 충족 여부는 판단하지 않습니다.

## 근거와 한계

현재 출처 장부에는 공식 채용 공고 23건(H1–H23), 공식 지침 5건(G1–G5), 한국 테크 기업의 역할 인터뷰 2건(G6–G7)이 있습니다. 지침은 역할·문서 관련 3건과 직무분류 관련 2건(G4 ILO·ISCO, G5 NCS)입니다. 공고에는 인사관리를 맡는 팀장, 기술·제품·프로젝트 리드, 관련 시니어 역할이 포함됩니다. 각 사례의 책임과 권한 범위는 따로 기록합니다. FDE 두 사례와 당근 PM 공고에서는 사람을 관리하는 팀장 역할을 확인하지 못했습니다. G6·G7은 각각 2020년·2022년의 역할 설명이며 채용 공고 수에 포함하지 않습니다.

15개 기능 모두에 실제 책임을 설명하는 공고를 연결했습니다. 0.3.0에서 제조 생산(H15), 고객지원(H16), 시설 유지보수(H17), EHS(H18), 준법(H19), 대외 정책관계(H20)를 전담하는 직무의 공고를 보완했습니다. **각 기능의 모든 하위 직무·산업을 조사했다는 뜻은 아닙니다.** 의료·교육·비IT 연구·법률 자문처럼 새로 다루는 구체적인 직무는 그 직무의 자료를 다시 조사합니다. 인접 직무의 공고 요건을 대신 적용하지 않습니다.

공고 사례는 고용주가 공개한 요구사항을 담습니다. 합격자의 이력서 원문·입사 결과를 확인한 사례나 시장 전체를 대표하는 표본은 아닙니다. 대학 지침은 교육을 위한 권고이고, ATS 문서는 해당 제품의 동작 설명입니다. 자료마다 근거의 성격을 구분합니다. ILO·NCS 자료는 분류 설계에 참고했으며, F01–F15와 공식적으로 대응하거나 이 분류의 MECE를 인증하는 자료는 아닙니다.

기존 실행 기록은 계산 테스트와 소수의 합성 과제에 한정됩니다. C(영업·구매)·D(경영지원)는 MECE를 반영하기 전 후보를 관찰한 기록입니다. 0.2.0의 E 과제에서는 25개 합성 사례가 한 번의 적용에서 수용 기준을 충족했습니다. 일부 입력은 외부 조사를 금지했으므로, 그때의 보류 판정으로 0.3.0의 기본 조사 동작을 검증했다고 볼 수는 없습니다. 외부 조사를 허용한 후속 적용 결과는 [직무 조사·이유 검증](evaluations/role-research/review.md)에 따로 기록했습니다. 한 번의 합성 과제 결과를 일반적인 성능 향상, ATS 점수, 서류 통과율, 채용 성공으로 확대하지 않습니다. 실제 지원자의 자료와 기업 시스템을 이용한 검증은 별도 과제입니다.

개인 이력서·연락처·보상정보·사내 원문을 저장소에 넣지 않습니다. 추가 개발 범위와 미완료 항목은 [제품·기술 Gap 기준선](docs/product-technical-gap-baseline.md)을 참조하세요.
