# 검증 기록 — 2026-11-08

## 범위와 절차

스킬 없이 합성 과제 A를 1회 실행하고, 최초 스킬로 과제 A·B를 각각 1회 실행했다. 코칭 표현을 보완한 뒤에는 새 문맥에서 과제 B를 1회 더 실행했다. 모든 실행은 별도 대화 문맥에서 합성 입력을 사용했다. 작성자와 실행 에이전트는 다르지만, 표본이 작고 무작위·맹검 방식의 성능 비교도 아니므로 일반적인 효과를 계산하지 않는다.

초기 기준 응답은 핵심 사실을 이미 보존했다. 관찰하지 않은 실패를 만들어 새 스킬의 효과로 보고하지 않는다. 면담 개최를 코칭으로 확대하는지 확인하는 항목은 최초 B 출력 뒤에 회귀 평가 기준으로 추가했다. 이를 사전에 정한 지표처럼 보고하지 않는다.

## 실제 관찰

| 실행 | 원문 | 결과 |
| --- | --- | --- |
| 스킬 없음 / A | [기준 응답](baseline-response.md) | 118개월·9년 10개월을 유지하고, 인원·역할·성과·미래 계획을 구분했다. |
| 최초 스킬 / A | [적용 응답](pressure-response.md) | 과제 A의 8개 항목을 충족했다. 세 항목이 같은 프로젝트에서 맡은 영역이라는 점도 구분했다. |
| 최초 스킬 / B | [최초 출력](positive-response-v1.md) | 인원·예산·성과·인과를 적절히 구분했다. 그러나 면담을 개최한 사실을 `정기적인 코칭을 운영`으로 확대해 썼다. |
| 보완 스킬 / B | [새 출력](positive-response-v2.md) | 공식 권한·채용 실적을 유지하면서 면담 대상·주기만 썼다. 코칭 내용은 별도 근거가 필요하다고 밝혔다. 나머지 B 기준도 충족했다. |

SKILL의 판단표와 evidence-workflow에 정기 면담, 구체적인 코칭 행동, 육성 결과를 구분하는 내용을 추가했다. 면담을 코칭으로 확대하는 출력을 관찰한 뒤 지침을 수정하고, 새 문맥에서 보완 결과를 확인했다. 이 한 번의 재실행은 전반적인 성능 향상을 입증하지 않는다.

과제 A에서는 파일 렌더링을 요청하지 않았고 실제 지정 양식 파일도 없었다. 표 형태의 텍스트 원고를 유지했는지만 확인했다. 실제 DOCX/PDF 조판·ATS 파싱·지원서 제출은 시험하지 않았다.

## 계산기

계산기 파일을 구현하기 전에 9개 테스트를 실행해 9개 모두 실패하는 것을 확인했다. 구현 후에는 같은 테스트를 모두 통과했다. 테스트는 기간의 포함·제외와 중복·동일·분리 여부, 현재 재직, 잘못된 월·역전·미래 날짜, 명시적 포함 여부, 제외 사유, 종료일 누락을 검사한다. 최초 실패는 기능이 없는 상태를 확인한 결과이며, 오류가 있는 기존 계산 구현과 비교한 결과는 아니다.

```bash
python3 -m unittest discover -s tests -v
```

최종 계산 테스트는 **9/9 통과**했다. 스킬 형식 검사도 통과했으며, 설치 폴더의 로컬 Markdown 링크가 가리키는 파일도 모두 확인했다.

개인 스킬을 저장한 뒤 조정된 설치 경로에서도 형식 검사와 같은 9개 테스트를 통과했다. 설치본의 본문·참조 자료·계산기는 배포 원고와 바이트 단위로 일치한다. 플랫폼이 `agents/openai.yaml`에 아이콘·제품 메타데이터를 추가했으며, 작성한 표시 이름·설명·기본 프롬프트는 그대로 유지된다. `manifest.json`에는 저장소 배포 원고의 해시를 기록한다.

응답 원문 두 파일에서 줄 끝의 두 공백은 Markdown 줄바꿈 표기다. 원문을 보존하기 위해 유지했으며, Git 공백 검사가 이 부분에 표시하는 경고를 코드 오류로 세지 않는다.

## 출처 확인

고용주 공고 4건(정식 관리직·과장~팀장급·기술 리드·프로젝트 리드)과 지침 3건을 직접 열람했다. SK AX·SK telecom 공고의 `Application closed` 표시, Coupang에 표시된 업데이트일, GitLab의 페이지 수정일, Greenhouse의 수정일을 대조했다. INTERX의 공식 상세 본문도 별도로 읽었으나 게시·마감일과 실제 접수 가능 여부는 확정하지 않았다.

채용 공고를 합격자 사례로 사용하지 않는다. [출처 장부](../skills/team-lead-resume/references/hiring-cases.md)에는 출처별 요구와 편집 판단을 구분해 적었다. Coupang 페이지의 서울 근무 표시와 영문 Singapore 자격 문장은 서로 맞지 않아 지원 자격 확인 대상으로 남겼다.

## 판본과 한계

공개 저장소의 최초 배포 커밋은 `94088b382bba044b0081da56649f0f53573128e8`이다. 원격 `main`을 다시 조회해 해당 커밋을 가리키는지 확인했다. 24개 파일의 전체 Git 트리 `9fd6691899853795c3fa7986cf95a210bec27d03`도 검증한 로컬 판본과 일치했다. 이 배포 커밋은 이후 완료 상태를 기록한 문서 수정과 구별한다.

별도 검토자는 스킬 본문·참고 문서·계산기·README·명세·평가 기준·합성 입력을 읽었으며, 커밋을 막을 실질적인 결함을 발견하지 못했다. 검토 시점의 계산 테스트 9개도 통과했다. 다만 그 검토자는 마지막에 추가된 이 검증 기록과 B 재실행 원문의 검토, 모든 링크의 검사를 완료하지 않았다. B 출력과 설치 폴더의 링크·파일을 대조한 작업은 작성자가 수행했다.

최초 스킬 파일의 SHA-256은 후속 보완 전 파일을 재구성해 기록하지 않는다. 실행에 사용한 경로의 판본을 처음부터 모두 고정해 두지 않았으므로, 출력 비교를 모든 판본이 고정된 실험이라고 주장하지 않는다. 최종 배포 파일의 해시는 `manifest.json`에 별도로 기록한다. 이 해시는 최종 배포를 확인하는 용도이며 과거 실행의 해시로 소급하지 않는다.

남은 검증은 허가받은 실제 사용자 자료에 대한 적용, 문서별 실제 렌더링, 직무·업종 확대, 채용사 시스템별 파싱 확인이다. 채용 효과·합격률·모든 ATS와의 호환성은 검증 범위 밖이다.
