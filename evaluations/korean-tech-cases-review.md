## 책임과 설명 검토

- H21–H23의 제품 책임을 F02에 연결했다. 소속 PO 육성·기술팀 코칭은 관리 범위로 기록하며 자동으로 F11을 부여하지 않는다.
- H23은 신설 이유와 사업 책임과의 경계를 확인했으므로 새로운 명칭만을 이유로 미확정 처리하지 않는다. 공고에 명시되지 않은 인사권은 별도 확인 사항으로 남긴다.
- G6·G7은 과거 역할을 설명한 자료다. 이를 현재 공고·사람 관리 권한·완료 실적으로 확대하지 않는다.
- 비교표의 ‘왜?’ 질문은 편집 판단으로 표시했다. 회사의 직무 목적을 지원자 개인의 과거 동기·인과로 옮기지 않는다.
- 별도 검토 에이전트는 이미 열람한 H22·H23 원문을 사례 본문, 관련 비교표 행, F02 연결과 대조했다. 사실·권한·분류·날짜에서 오류를 발견하지 못했다. H21·G6·G7 원문은 이 추가 검토에 포함되지 않았다.

## 실행한 검사

- 정식 개인 스킬 경로에서 `quick_validate.py`를 실행해 통과했다.
- 같은 경로의 계산기를 대상으로 `TEAM_LEAD_SKILL_DIR=... python3 -m unittest discover -s tests -v`를 실행해 기존 9개 테스트를 모두 통과했다. 실행 환경은 Python 3.12.14였다.
- 새 출처는 공식 공고 3건과 역할 인터뷰 2건으로 나눴다. 기존 지침 5건을 포함한 장부의 사례 번호는 H1–H23, G1–G7이다. 과거 인터뷰는 공고 수에 포함하지 않는다.

배포 파일 해시는 저장소 루트의 `manifest.json`을 기준으로 한다.

## 저장과 배포 대조

- 개인 스킬 저장 커밋: `e3470128e9eb9450ad86e142c06942a2cb203e6b`.
- 저장 후 원격 활성 경로의 파일 8개를 다시 조회해 SHA-256을 대조했으며 모두 일치했다. 비활성 경로에 같은 스킬이 없다는 것도 확인했다.
- 설치본에서 직접 작성한 파일을 공개 배포 폴더로 내보냈다. 배포 파일은 기존과 같은 7개이며 플랫폼의 아이콘·정책 메타데이터는 배포 YAML에 복사하지 않았다. YAML에서 직접 작성한 인터페이스 값 3개는 설치본과 일치한다.
- 개인 스킬 안의 상대 파일 링크 11개가 실제 파일로 연결되는지 확인했다. H1–H23과 G1–G7의 일련번호·건수도 대조했다.
- 공개 반영은 기준 main에서 생성한 전체 트리가 로컬 커밋 트리와 일치하는지 확인한 뒤 일반 ref 갱신으로 진행한다. 최종 공개 커밋은 이 문서를 포함한 Git 이력에서 확인할 수 있다.

## 검증의 한계

이번 검토에서는 출처와 문서 변경 내용을 대조했다. 새 문맥의 이력서 작성 행동 실험·ATS 시험·실제 지원자 평가·채용 결과 검증은 수행하지 않았다. 0.3.0과 이전 버전의 합성 실행 기록은 해당 판본의 이력으로 유지한다. 한국 기업 몇 곳의 자료를 시장 전체의 대표 표본이나 모든 팀장의 공통 요건으로 일반화하지 않는다.
