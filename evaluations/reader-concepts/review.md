# 외부 독자를 위한 개념 조사 규칙 검증

확인일: 2026-11-08. 지원자와 비공개 과제 자료는 합성이다.

## 변경과 근거

이전 지침에는 약어를 풀어 쓰고 전문 용어의 의미를 필요한 만큼 설명하라는 안내가 있었다. 이번에는 독자 배경 판단, 공식 공개 자료·승인된 내부 근거 조사, 동명 개념과 시점 확인, 공개 범위 보호, 본인 기여와 개념 설명의 구분을 실행 순서로 명시했다. 독자에게 충분한 설명과 단순 맞춤법 작업의 범위도 보존한다.

C-Cube는 [효성 공식 소개](https://blog.hyosung.com/4960)의 본문을 직접 확인했다. 2020-10-13 게시, 2026-11-08 확인. 고객 중심 경영 활동의 목적과 활동 지원 시스템을 구별하는 예로만 사용했으며 실제 지원자의 경력·성과 자료로 사용하지 않았다. 변경 검토자도 원문을 따로 읽고 이 설명이 부합한다고 확인했다.

## 적용 절차

1. 스킬 변경 전에 [입력](input.md)과 [판정 기준](criteria.md)을 기록했다. 기존판으로 작성한 [기준 출력](baseline-output.md)과 [판본 해시](baseline-version.json)를 보존했다.
2. 수정판으로 새 문맥에서 A·B·C·D를 작성했다. 작성자에게 이전 출력과 판정 기준을 제공하지 않았다. [수정판 출력](revised-output.md)과 [최종 판본 해시](revised-version.json)를 보존했다.
3. 변경 문구를 별도로 검토했고 필수 수정은 없었다. 출력도 다른 검토자가 입력·기준과 대조했다. [독립 검토](independent-review.md)는 문장의 적합성과 도구 행동의 검증 한계를 구분한다. 익명·맹검 비교 실험은 아니다.

## 결과와 한계

기존판과 수정판 모두 네 사례의 제출 문장·처리 방침이 기준에 부합했다. 수정판은 공개 개념의 목적을 설명하고, 비공개 명칭 대신 허용된 기능을 쓰며, 전문가에게 충분한 표현을 유지하고, 뜻을 모르는 약어를 추정하지 않았다. 따라서 이번 변경을 성능 향상이나 관찰된 실패의 해결로 주장하지 않는다. 사용자 요구를 재사용 가능한 명시적 규칙으로 보강한 것이다.

실제 외부 검색 미사용과 모든 후속 행동까지 출력만으로 검증하지 않았다. 원문을 읽었다는 작성자의 보고와 독립 검토자의 직접 원문 확인을 구분했다. 네 합성 사례는 일반 성능이나 실제 채용 효과를 입증하지 않는다. DOCX/PDF 조판과 지원 시스템은 검사하지 않았다.

## 실행한 검사

- 두 개인 스킬의 구조·이름·frontmatter 검증 통과.
- Markdown 상대 파일 링크와 git diff --check 통과.
- team-lead-resume-skills 전체 단위 테스트 9건 통과. 계산기는 변경하지 않았다.
- career-description-skills에는 실행형 테스트 스위트가 없어 위 합성 적용과 구조 검사를 수행했다.
- 앱 저장 상태, 원격 브랜치, CI 실행 상태는 별도로 확인해 보고한다. 이 기록 자체는 병합·배포 성공을 뜻하지 않는다.
