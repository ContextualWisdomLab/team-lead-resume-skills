# MECE 기능분류 검증 기록 — 0.2.0

기준일은 2026-11-08이다. 사용자의 후속 요구인 `직무가 MECE하게`를 반영했다. 이전에 10개 직무군으로 나눈 후보의 C/D 결과는 [별도 기록](review.md)에 남겼으며 최종 분류의 결과로 소급하지 않는다.

## 설계와 확인 범위

최종적으로 책임지는 산출물에 따라 F01–F15를 정의했다. 한 책임에는 기능 하나를 부여하고, 독립된 책임이 여러 개면 각각 나눈다. 대표 기능과 보조 책임을 분리하며, 정보가 부족해 기능을 알 수 없는 경우와 복합 직무의 대표 기능만 정할 수 없는 경우를 구분한다. 산업·기술·관리 범위·운영 대상·프로그램은 별도 속성으로 둔다.

상호 배타성은 각 책임에 기능을 하나만 배정했는지와 기능별 포함·제외 경계가 분명한지로 점검한다. 포괄성은 실제 공고의 책임 목록을 대조해 배정하지 않은 책임, 여러 기능에 배정한 책임, 중복으로 센 성과를 찾으며 점검한다. `기타`를 추가하거나 직함 하나를 골랐다는 이유로 모든 직무를 포괄한다고 주장하지 않는다.

ISCO와 NCS는 설계 원칙을 정할 때 참고한 근거다. 이 15개 기능은 공식 코드·공식 대응표·공인 MECE 분류가 아니다. 공고 근거는 기존 4건과 추가한 8건이며, 공고를 확보하지 못했거나 일부만 확보한 영역을 기능별로 표시했다. 15개 기능 모두에 전담 채용 공고가 있다는 뜻은 아니다.

## 합성 적용 설계

[E 입력](input-mece.md)은 25개 사례로 구성했다. F01–F15의 기본 예, 전문서비스 납품, 산업·기술 태그, 자체 검증과 별도 품질 책임, 여러 책임이 결합된 고객성공·경영지원, 정보가 부족한 AX·PMO 직함을 포함한다. [수용 기준](criteria-mece.md)과 [입력·스킬 해시](mece-version.json)는 실행 전에 기록했다.

실행자에게 당시 SKILL·필요한 참조 파일과 입력만 제공하고, 기대 코드·평가 기록·기존 출력은 읽지 않도록 했다. 새 문맥에서 한 번 적용한 것이며, 모든 직업·산업을 빠짐없이 분류하는지나 같은 결과가 반복되는 빈도를 검증하는 실험은 아니다.

## 실제 적용 결과

작성자가 [E 실제 응답](mece-response.md)을 수용 기준 E01–E25와 대조했다. **25개 사례 모두 기준을 충족했다.** E01–E15는 각 사례의 책임에 맞는 기능으로 분류했으며, 산업·외부 납품·신규 문서 작성 여부에 따라 기능을 바꾸지 않았다.

- E16·E18은 직함·기술·회의 정보만으로 기능을 확정하지 않았다.
- E17은 이용 정착 F09와 갱신 계약 F05를 나누고, 입력에 명시된 대표 평가 기준에 따라 F05를 대표 기능으로 정했다.
- E20은 F01·F10의 책임을 분류하되 대표 기능은 미확정으로 유지했다.
- E19·E21–E25는 제작물 인도, 직접 수업, 법률 통제, 개발자의 자체 검증, 설비 유지, 생산 실행의 경계를 보존했다.

실행자가 실제로 읽었다고 보고한 파일은 SKILL과 role-families다. 별도 파일 목록을 제외한 사용자 응답을 그대로 보존하고 출력 해시를 기록했다. 적용을 시작한 뒤에도 스킬 해시를 대조했으며, 이 적용 결과에 따라 지침을 추가로 수정하지는 않았다. 25개 합성 사례를 한 번 관찰한 결과이므로 모든 직업의 MECE를 인증하거나 일반적인 성능 개선을 입증하지 않는다.

## 독립 검토 범위

별도 검토자는 최종 SKILL, role-families, hiring-cases의 G4·G5를 읽었다. 분류 단위·경계, 속성의 분리, 복합 책임, 미확정 처리, 근거 해석에서 실질적인 결함을 발견하지 못했다. 이 검토에서는 새 적용 출력을 채점하거나 모든 직업을 포괄하는지 판정하지 않았다.

## 기본 검증

최종 후보는 스킬 형식 검사를 통과했다. 설명은 300자이며 F01–F15가 순서대로 한 번씩 정의되어 있다. 설치 폴더의 로컬 참조에 빠진 파일은 없었다. 기존 계산 테스트 9개도 모두 통과했다. 계산기와 외부 의존성은 변경하지 않았다.

## 설치·배포 원고 대조

최종 스킬을 개인 스킬의 활성 경로에 저장한 뒤 원격을 다시 조회했다. 본문·참조 파일의 해시, 계산기, 표시 메타데이터를 대조해 검증한 E 후보와 작성 파일의 내용이 일치함을 확인했다. 이후 공개 배포 폴더에 완성본을 반영하고 배포 파일 7개의 SHA-256을 `manifest.json`에 기록했다. 플랫폼이 추가한 아이콘·제품 메타데이터는 공개 배포 YAML에 복사하지 않았으며, 작성한 표시값은 의미가 같음을 확인했다.
