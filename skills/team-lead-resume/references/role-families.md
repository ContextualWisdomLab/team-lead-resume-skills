## 분류 대상과 단위

기업·기관의 팀장급 이력서에서 **독립적으로 책임지는 최종 산출물·성과**를 분류한다. 직함 한 개가 분류 단위는 아니다. 경영지원·AX·SCM처럼 여러 기능을 맡는 직무는 책임 단위로 나누고, **한 책임에는 한 기능 코드만** 부여한다. 같은 성과를 여러 기능의 별도 실적으로 중복 계산하지 않는다.

이 문서는 ISCO의 주요 수행 업무 관점과 NCS의 분류 원칙을 참고한 **사용자 정의 기능분류**다. F01–F15는 공식 직업 코드가 아니다. 산업·기술·관리 범위를 별도 속성으로 두는 것은 이 스킬의 설계 선택이다. 출처와 한계는 [G4·G5](hiring-cases.md)를 확인한다.

## 새로 다루는 직무를 조사하는 순서

**처음 보는 직무명, 기존 장부에 없는 직무, 책임·성과 기준이 불명확한 직무는 조사 대상이다.** 기존 표에 전용 행이나 공고가 없다는 이유로 직무 전체를 미확정으로 넘기지 않는다. 지원자가 준 공고에 필요한 책임이 충분히 설명되어 있으면 그 근거를 사용하고, 명칭만 있거나 회사별 차이가 중요한 경우 다음 절차로 보완한다.

1. 목표 기업의 공식 상세 공고와 역할 설명을 먼저 읽는다. 없으면 직무명·통용되는 다른 이름으로 **서로 다른 고용주의 공식 자료 2건**을 찾아 공통 책임과 차이를 비교한다. 2건을 확보하지 못하면 읽은 자료와 조사 범위를 밝히고 확인된 책임부터 정리한다. 검색 요약만으로 본문을 읽었다고 하지 않는다.
2. 각 자료에서 **직무의 목적·해결하는 문제, 최종 산출물, 결정권, 구현·운영·고객 접점의 범위, 성과 기준, 협업·인사관리 범위**를 추출한다. 왜 그 책임이나 지표가 중요한지 설명할 수 있는 업무 맥락도 모은다. 공고가 말한 내용과 작성자의 해석을 구별한다.
3. 공통 책임과 기업별 변형을 나누고 아래 절차로 기능을 배정한다. 새 직무명을 새 상위 기능으로 자동 추가하지 않는다. 기존 경계에 맞지 않는 책임은 실제 산출물·인접 기능·차이를 조사해 경계를 보완하거나 추가 기능을 제안한다. `기타`로 덮지 않는다.
4. 원문 URL·고용주·직무명·확인일·게시/마감일·열람 상태, 분류 근거와 남은 차이를 기록한다. 새로 확장한 직무에는 그 직무를 직접 다루는 근거를 연결한다. 인접 직무의 공고만으로 채용 요건을 대신하지 않는다.
5. 조사가 끝나면 확인한 책임과 그 이유를 제시한다. 아직 특정할 수 없는 사항은 `신규 직무라 미확정`이 아니라 **그 회사의 계약 책임 여부, 인사권, 서로 다른 결과의 우선순위**처럼 질문의 대상을 한정한다. 지원자 본인의 경험·판단은 경력 자료로 별도 확인한다.

외부 조사를 사용자가 제한했거나 접근이 막힌 경우에는 가능한 제공 자료로 진행하고 실제 제한과 필요한 자료를 알린다. 조사하지 못한 사실을 조사 결과처럼 쓰지 않는다. 완전한 자료를 기다리느라 확인된 책임·이력서의 작성을 중단하지 않는다.

### 조사 적용 예: FDE

[H13·H14](hiring-cases.md)의 OpenAI와 Palantir 공식 FDE 공고는 고객 문제를 파악하고 시스템·애플리케이션을 설계·구현·배포하는 책임을 명시한다. 이 두 사례의 기술 산출물은 F03에 대응한다. OpenAI는 구축한 시스템의 도입과 업무 흐름의 효과를 성과 기준으로도 제시한다. 도입·활용 성과를 독립적으로 책임지면 F09를 별도 책임으로 기록한다. 고객과 협업한다는 사실만으로 F05의 계약·매출 책임을 부여하지 않는다.

따라서 직무명만 보고 미확정으로 남기는 대신 **고객 문제에서 운영 배포까지 맡는 기술 역할이라는 조사 결과와 분류 이유**를 설명할 수 있다. 두 공고는 정식 팀장·사람 관리자 공고로 확인한 사례가 아니다. FDE Lead의 직속 인원·평가·채용 권한은 해당 기업의 공고에서 추가 확인한다. 모든 기업의 FDE를 같은 역할로 단정하지 않는다.

## 확인한 책임을 분류하는 순서

1. 책임 문장을 **대상·최종 산출물·책임 범위·근거**로 정리한다. 서로 다른 결과의 책임이 함께 있으면 나눈다. 결과를 만드는 과정의 모든 행동까지 별도 직무로 쪼개지는 않는다.
2. 표의 포함·제외 경계로 기능 하나를 고른다. 같은 책임에 두 코드가 남으면 최종 산출물 또는 승인·성과 책임을 다시 확인한다. 프로젝트의 회의·일정 관리만으로 새로운 기능을 만들지 않는다.
3. 직무 전체의 대표 기능은 **공고의 핵심 결과 책임 → 명시된 평가 우선순위 → 확인된 업무 비중** 순으로 정한다. 비중은 추정하지 않는다. 직무 조사를 거친 뒤에도 독립 결과들의 우선순위가 동률이거나 자료에 없으면 대표 기능만 보류하고, 확인된 책임별 분류와 그 이유를 제시한다. 회사별 비중 질문을 직무 전체의 미확정으로 확대하지 않는다.
4. 산업·기술·관리 범위는 아래의 별도 속성으로 기록한다. 원래 회사의 직함·조직명을 유지한다. 기능 코드는 분석용이며 제출 이력서에 자동 삽입하지 않는다.
5. 공고의 모든 독립 책임을 대조하여 **미배정·다중배정·반복 계상**이 없는지 확인한다. 누락된 책임을 일반 운영이나 기타에 억지로 넣지 않는다. 자료가 부족한 경우와 분류 경계 자체가 부족한 경우를 구분한다.
6. 분류 경계의 공백은 해당 직무를 조사한 근거와 책임·후보 기능·이유로 보완한다. `기타` 항목을 추가하거나 대표 라벨 하나를 골랐다는 이유로 포괄성을 충족했다고 주장하지 않는다. 공공·비영리·특수 전문직은 실제 업무·자격을 해당 분야의 공식 자료에서 조사한다.

### 기능과 분리하는 속성

| 속성 | 예시·기록 방식 |
| --- | --- |
| 산업·서비스 분야 | 제조, 금융, 의료, 교육, 유통, 공공 등 실제 사업 분야 |
| 기술·전문 수단 | AI, 데이터, 클라우드, ERP, 특정 공법·장비. 사용 사실과 수준 확인 |
| 역할·관리 범위 | 실무, 전문 리드, 프로젝트 리드, 사람 관리자. 직속 인원·평가·채용·예산 권한을 각각 확인 |
| 운영 대상 | 내부 조직·외부 고객, 지역, 고객군, 제품·시설·법인 범위 |
| 프로그램·업무 방식 | AX·DX, SCM, ESG, PMO, 프로젝트·상시 운영. 명칭만으로 기능 확정 금지 |

## 지표의 정의와 집계 범위

수치를 쓰기 전에 **지표 정의 → 대상·기간·단위·분모 → 기준값·비교값·목표 → 자료·산식 → 본인 행동·팀 결과·승인권**을 확인한다. 내부 작업표 전체를 제출 문서에 넣을 필요는 없다.

| 자료 | 유지할 구분 |
| --- | --- |
| 영업·마케팅 | 수주·인식 매출·GMV·미체결 기회를 구분한다. 목표 달성률의 대상을 밝힌다. 확률 가중 예측에는 단계·확률·기준일이 필요하다. 광고 귀속과 증분 효과를 구분한다. |
| 구매·비용 | 협상·실제 적용 단가, 예상·실제 수량, 사양·통화·기간을 맞춘다. 예상 물량을 곱한 금액은 조건부 예상치다. 실현 절감은 실제 적용·수량·비교 조건으로 대조한다. |
| 예산·손익 | 수립·조정·승인·집행의 주체, 목표·전망·실적, 매출·이익·현금, 마진율 차이·상대 변화를 구분한다. |
| 채용·운영·서비스 | 시작·종료 사건, 영업일·달력일, 평균·중앙값, 완료·미완료 집단, 직무·물량·난도 변화를 확인한다. 연말 인원을 임의로 평균 재직 인원으로 대체하지 않는다. |
| 제품·품질·기반 운영 | 개발 완료·출시·사용·사업 결과, 모집단·코호트·관찰 기간, 오류·반품 분모, 부하·가용성·복구 기준과 동시 변경을 확인한다. 예상 시간 절감과 실현 순절감을 구분한다. |

숫자가 없으면 확인된 판단·협상·설계·운영 범위와 산출물을 쓴다. 지표가 표에 있다는 이유로 수치를 만들지 않는다. 계산·인과·본인 기여의 공통 기준은 [증거 절차](evidence-workflow.md)를 따른다.

## 채용 근거의 확보 범위

기능분류의 범위와 조사한 공고의 범위는 다르다. [채용 사례 장부](hiring-cases.md)의 한 공고가 여러 독립 책임을 포함할 수 있으며, 같은 책임을 중복 분류한다는 뜻은 아니다.

| 기능 | 확인한 관련 사례 | 확보한 범위·남은 공고 조사 |
| --- | --- | --- |
| F01 | H5, H6 | 사업계획·전략 재무의 일부 책임 |
| F02 | H10 | 소프트웨어 제품·성장 기획 |
| F03 | H1, H2, H4, H10, H13, H14 | 소프트웨어·데이터·AX·FDE 설계·개발. 비IT 연구·창작은 목표 직무별 추가 조사 |
| F04 | H9 | 북미 커머스·브랜드 마케팅 |
| F05 | H8 | B2B 영업 실행·팀 운영 |
| F06 | H11 | 글로벌 소싱·공급사 관리 |
| F07 | H12 | 3PL·국내외 물류 |
| F08 | H15 | 제조 도장 생산·작업자 운영. 시공·의료·교육 등은 해당 직무를 별도 조사 |
| F09 | H16; 도입 관련 H13 | 고객지원 팀 운영과 별도 기술 직무의 도입 책임. 전문 고객성공·계약 책임은 목표 공고로 구분 |
| F10 | H5, H6 | FP&A·예산·통제 중심. 회계·감사 전체 요건 아님 |
| F11 | H7 | 채용 전략·운영·코칭 중심. HR 전체 요건 아님 |
| F12 | H1, H2, H3, H17 | IT·플랫폼과 비IT 시설 유지보수·가용성. 행정 등 다른 운영 대상은 별도 조사 |
| F13 | H18 | 반도체 고객 현장의 전담 EHS 통제. 제품 품질 승인 등은 해당 직무를 조사 |
| F14 | H19; 일부 H6 | 금융 준법 프로그램과 예산 내부 통제. 법률 자문·감사는 해당 직무를 조사 |
| F15 | H20; 일부 H5 | 대외 정책관계와 IR 자료 지원. 언론·투자자 관계 전담은 해당 직무를 조사 |

15개 기능 모두에 실제 책임을 다루는 공고 근거를 연결했다. 이 표는 각 기능의 모든 하위 직무·산업을 조사했다는 뜻이 아니다. 다음에 새 직무를 다루면 위 조사 절차로 그 직무의 근거를 확보한다. 공고 조사 없이 채용 요건·필요 자격을 보태거나 특정 공고의 연수·권한·지표를 기능 전체의 공통 기준으로 일반화하지 않는다.
